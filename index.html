A

About

How a lab manager ended up writing production software.

I came to software from the bench. I set up Oxford Nanopore sequencing in-house, prepared and multiplexed libraries for Illumina and Nanopore, and built the 16S, RNA-seq and metagenomics workflows that processed what came off them — and somewhere in there I became the person who also built the tools. Today I run daily operations for a molecular biology section at Aarhus University, coordinate an international research consortium, and keep building.

The hard part of writing software for a laboratory is rarely the code. It is that the code has to be right about something biological it does not understand.

That is the thread through everything below. Most developers can build the system; fewer can read the data running through it. I have spent years on both sides of that line, which is why the lab’s ordering and sample database, an offline assistant my colleagues use daily, and a phenotyping pipeline that cleared months of manual measurement all look like the same job to me.

Lab systems & infrastructure

The software a molecular biology section runs on, built and operated in-house.

  1. 05

    Lab server

    In service

    The section’s shared web server: a map bank of 5,900+ plasmids (11,700+ map files) with bench tools — clone verification against Sanger reads, primer design, Golden Gate assembly with overhang diagnosis, Gibson assembly, BLAST — and a genome browser for any genome. Run as a service, not a script: auto-deploy, and load tests that found the bottleneck; a cache then took browsing at 16 simultaneous users from 4.8 to 109 requests a second. For its first genome, 49,521 of 49,532 coding sequences match an independent reference annotation.

    • FastAPI
    • SQLite
    • Docker
    • Caddy
    • Biopython
    • Read the code (MIT template) ↗
  2. 06

    Sequencing databases

    In progress

    Scattered RNA-seq studies consolidated for the section. Barley: 535 samples across 19 studies, with a harmonised count matrix for the first 8 studies, differential-expression contrasts and a browsable results page. Lotus japonicus: 535 samples aligned and counted against two reference genomes, the shared matrix in progress. Plus a bacterial whole-genome pipeline built for about 96 isolates and validated before it is trusted: on the first six it matches the earlier CheckM completeness and contamination values exactly, and batching cut eggNOG annotation from 80 to 6.6 core-hours.

    • gwf
    • SLURM
    • STAR
    • DESeq2
    • CheckM

  1. 12

    genome-decoded

    Open source

    Turns a consumer DNA download (MyHeritage, FTDNA, 23andMe, AncestryDNA) into a readable, honest report — ancestry, drug response, HLA type, polygenic scores and ClinVar variants — without the genome ever leaving your machine. On the NA12878 reference sample, its HLA calls match the published typing at 10 of 10 alleles and its drug-gene calls exactly match the CDC GeT-RM consensus for 10 of 12 genes, with the other two agreeing in part.

Independent research

Done on my own time. The method is the point; the subject is incidental.

  1. 16

    dmi-capture

    Ongoing

    A storm-surge forecast archive that nobody else keeps. The Danish Meteorological Institute holds only a day or two of ocean forecasts and publishes no history, so a day not captured is lost for good. A capture-and-evaluation pipeline on an always-on box, with questions about the data put to DMI’s scientists and their answers kept on record.

    • Python
    • scheduling
    • forecast verification
  2. 17

    aurora-watch

    Research

    An aurora and cloud image classifier study with an external all-sky camera network. Agreement is measured honestly: in a first test of 46 frames, two raters agreed on 97.8 % yet κ was only 0.657, because chance agreement was already 93.7 %. Solar geometry computed from scratch, matching the camera’s own overlay to 0.007° in elevation.

    • Python
    • computer vision
    • inter-rater statistics
